# Company lookup and planning

M3 resolves reporting companies and produces a bounded research plan. Researchers,
evidence extraction and answer writing are the next milestones.

```bash
uv run python -m agents.planner "What was NVIDIA's revenue in fiscal 2026 and its growth vs fiscal 2025?" --today 2026-10-01
uv run pytest -q
uv run python -m evals.planner --name planner_m3
```

The CLI prints resolution metadata, the research brief, exact periods, filing
fetches, search intents and warnings. `--budget` caps planned **search credits**
(default 16); searches are not executed. Extraction spending is reserved for M4.
Credentials are loaded programmatically and never printed.

## How it works

One small Nebius call extracts company mentions. Python matches names/aliases
against SEC tickers and reads the submissions metadata. Share classes collapse
by CIK. Ambiguous names and uncovered companies stay unresolved. NVO is covered
by EDGAR as a 20-F filer; a foreign company without an EDGAR registrant is not guessed.
Cargill stays unresolved but has a sourced private-company calendar.

The calendar reads dated XBRL duration contexts, including prior-year comparisons,
and uses annual filing dates to establish fiscal labels. It infers week-based
calendar rules from historical ends. This handles Target's starting-year convention,
Costco's 16-week Q4 and Micron's 53-week year. Explicit periods, quarter ranges,
comparisons, TTM calculations and inclusive news windows are bound in code.

One further Nebius call plans the metrics and retrieval intents. It selects
validated period keys when explicit question rules cannot bind the scope. Python
enforces minimum researcher coverage, known company IDs, the credit cap and query
lengths. No model re-planning or research loop is used. Available 8-K earnings
releases can be used before a 10-Q/10-K appears; unreported actuals are flagged
and their unavailable filing fetches are omitted.

`Qwen/Qwen3.8-27B` uses native JSON-schema output with reasoning disabled. The
installed LangChain Nebius adapter needs its existing OpenAI root client connected
for native schema parsing; `agents/models.py` contains this small compatibility fix.
Callbacks can be passed through both model steps to the existing tracing module.

## Verification

The [scorecard](../results/planner_m3_final_verified.md) records 30/30 correct company
checks, 25/25 exact fixed-question period checks, 30/30 required researcher checks,
zero errors and all budget/query limits satisfied. All five dynamic questions also
match their pinned October 1 period snapshot. Dates have zero tolerance; label
comparison preserves fiscal/calendar identity and aggregate actual/implied basis
while removing display descriptors and company prefixes. This measures planning,
not final-answer accuracy or retrieval quality.

The live benchmark sends only questions, as-of dates and public company/calendar
data to the model. Golden answers, evidence, company fields, lenses and expected
periods are used only for scoring. Its network allowlist covers both `httpx` and
the OpenAI SDK's `httpx2` transport: only Nebius requests are permitted. The final
run made exactly 60 such requests and no retrieval calls.

54 unit tests block socket connections. They cover resolution, fiscal calendars,
additional years and question variants, ambiguous/private companies, derived
periods, missing filings, share classes, credit limits and the benchmark allowlist.
Fixture responses are public SEC projections containing registrant metadata,
filing dates and deduplicated duration contexts, with numeric values omitted.
Their source manifest is in `tests/fixtures/edgar/manifest.json`.

To deliberately refresh fixtures (uses SEC, no Tavily):

```bash
uv run python -m scripts.save_sec_fixtures NVDA AAPL COST ORCL CSCO META CRM MSFT NKE WMT AVGO GOOGL GOOG DE HON HONA NVO MU AMZN TGT
```

Production SEC responses use a 24-hour local cache in ignored `results/sec/`.
Offline mode pins the saved responses regardless of cache age. The client sends
`SEC_USER_AGENT` with contact email and throttles/retries requests.

## Limits and sources

Future periods are projections, not reported results. Some companies schedule
53-week adjustments rather than follow a fixed calendar rule; those projections
must be confirmed against the next filing. The 8-K reporting check uses Item 2.02
and proximity to quarter end; M4 must read the release itself before using numbers.
Questions outside the explicit period rules use model-selected catalog keys and
can fail validation rather than silently invent an identity or date.

## Hardening and realistic validation

The original 30 questions are development regression tests. Their perfect M3
score is not independent evidence of generalization. A review found five scope
failures under ordinary rewording: `to` versus `through`, explicit calendar
quarters, year-first quarter lists, fiscal half-years, and company introductions
whose order differed from their local comparison clauses.

The fixes recognize these language families, preserve explicit calendar dates,
and bind local company mentions. Unsupported subannual wording defers to the
single structured planning call instead of being mistaken for an annual request.
The planning schema can select calendar quarters/half-years with owners. Multiple
half-year clauses defer rather than bind only their first clause. The prompt no
longer contains the Apple/Azure disclosure assertions or named-company calendar
examples; the public calendar catalog still supplies the actual reporting dates.
There is no extra model call or retrieval loop.

`evals/planner_ownership.json` adds expected owners without changing `golden.jsonl`.
Scoring compares each company-period pair, including fiscal identity and exact
dates, so correct dates with swapped owners fail. Grouping identical periods for
several companies is allowed; missing or duplicate ownership is not.

```bash
uv run pytest -q
uv run python -m evals.planner --name planner_regression
uv run python -m evals.planner --dataset validation --name planner_validation
```

80 offline tests pass. The live regression passes all checks on 30/30 questions,
with 25/25 fixed periods and 30/30 company-period ownership. Median planning time
is 3.27 seconds, mean tokens 6,355, and planned search credits 2.93 (not spent).
The final code also reproduces all 29 explicitly bound original scopes offline.
The remaining leadership question uses structured-model fallback.

The 18 validation requests were frozen before code changes. They cover Adobe,
Intuit, Home Depot, PepsiCo, JPMorgan and Taiwan Semiconductor, plus existing
companies at earlier as-of dates. Dates were checked against public SEC duration
contexts independently of `FiscalCalendar`; calendar/news windows use date
arithmetic. `planner_validation_sources.json` records the references. The pinned
validation ticker index has all 10,434 SEC entries, which avoids making company
resolution artificially easy with a shortlist. The original response snapshots
remain unchanged and no financial values are included in the new projections.

The **first result is 16/18 all checks**, with 17/18 correct period scopes. Both
misses concern the same acronym: extraction returns `TSMC`, which does not match
the SEC ticker `TSM` or its legal name. It stays explicitly unresolved. No alias
exception was added to make these cases pass. All researcher/budget/query checks
pass, as do both required missing/unreported flags. Median time is 3.06 seconds,
mean tokens 4,872, and planned search credits 2.17. No SEC/Tavily network calls
occurred in the evaluation; inference made 36 Nebius requests.

The validation file hash and pre-first-run production hashes are in its manifest.
A subsequent source review added two conservative guards for calendar-clause
ownership and multiple half-year clauses. The final code hashes are recorded
separately. A confirmation run again scores 16/18; this repeat is regression
confirmation, not independent evidence. Its median time is 2.80 seconds.

The validation command **exits 1** while those two known failures remain; results
are retained rather than hidden or the expectations weakened. This small set was
authored and checked by the developer, so it is not blind or human-verified. The
two related acronym cases are also not independent failures. These measurements
show useful generalization and a real resolution limitation; they do not establish
financial-answer accuracy or prove freedom from overfitting. Future tuning should
promote used validation cases to regression and reserve fresh questions before
making new generalization claims. A general source-validated alias mechanism is
the appropriate resolution follow-up; another named-company prompt exception
would not address the underlying limitation.

describes submissions metadata, XBRL endpoints, supported forms and the distinction
between fiscal and calendar frames. Cargill's
[published fiscal calendar](https://www.cargill.com/sustainability/2025-impact-report)
supplies its June–May convention while its EDGAR status remains unresolved.
Deere's [2025 annual report](https://www.sec.gov/Archives/edgar/data/315189/000110465925122321/de-20251102x10k.htm)
explains its scheduled 53-week adjustment; that uncertainty is preserved in warnings.
